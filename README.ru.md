# ozvix-logto-connector-vkid

Социальный коннектор, добавляющий вход через **современный VK ID** в [Logto](https://logto.io) OSS.

Под VK ID здесь понимается актуальный сервис авторизации VK (`id.vk.ru`, OAuth 2.1,
authorization code flow с PKCE `S256`), а **не** устаревший поток `oauth.vk.com`, который VK
объявил устаревшим и больше не поддерживает.

- Пакет: `@ozvix/connector-vkid` 1.1.0
- Идентификатор коннектора (factory id): `vk-universal`, target `vk`, тип Social, платформа Universal
- Лицензия: MPL-2.0
- English documentation: [README.md](README.md)

## Почему этот коннектор существует

Опубликованный вышестоящий пакет `@workingbit/connector-vk@0.0.4` **нельзя использовать как есть**
с Logto 1.46.0 — по двум независимым причинам, каждая из которых фатальна:

1. **Любой настоящий callback от VK ID не проходит валидацию.** Его guard ожидает в callback
   параметр `redirectUri`. VK ID присылает только `code`, `state`, `device_id` (и необязательный
   `type`); `redirect_uri` — это параметр _запроса_, а не callback. Поэтому guard отвергает каждую
   успешную авторизацию.
2. **Logto 1.46.0 молча пропускает пакет.** В нём жёстко зафиксирован `@logto/connector-kit`
   ровно версии `5.1.2`. Logto 1.46.0 содержит `@logto/connector-kit` 5.2.0, а загрузчик
   коннекторов отказывается загружать пакет, если объявленный диапазон не покрывает
   установленную версию. В результате коннектор не появляется в Admin Console.

Кроме того, вышестоящая реализация требует `clientSecret`, который обмен кода на токен в VK ID не
использует (в VK ID вообще нет параметра `client_secret`), игнорирует проверку `state`, которую
VK ID документирует как обязательную, и может сериализовать access/refresh-токены в тело ошибки,
которое Logto пишет в лог.

Этот коннектор — переработанная версия с устранёнными проблемами. Все находки с доказательствами
описаны в [SECURITY-AUDIT.md](docs/SECURITY-AUDIT.md), архитектура и связь с вышестоящим кодом —
в [ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Что делает коннектор

- Авторизация: OAuth 2.1 authorization code + PKCE (`S256`), `https://id.vk.ru/authorize`.
- Обмен кода на токен: `POST https://id.vk.ru/oauth2/auth` — без `client_secret`; конфиденциальные
  приложения VK ID передают вместо него `service_token` и должны обращаться с разрешённого IP.
- Профиль: `POST https://id.vk.ru/oauth2/user_info?client_id=…`, access token передаётся в теле
  формы. Коннектор передаёт в Logto:
  - стабильный идентификатор пользователя VK (используется как subject социальной идентичности);
  - отображаемое имя, собранное из `first_name`, `last_name` и (если есть) `patronymic`;
  - URL аватара — только если это абсолютный `http(s)`-URL;
  - e-mail и номер телефона — **только** если включены `syncEmail` / `syncPhone`.
- Хранилище токенов: если в Logto включено хранилище токенов (Secret Vault), коннектор передаёт
  туда access token, refresh token, `id_token`, `expires_in`, `scope` и `token_type`. При этом
  **обновление токенов не реализовано** — см. [Ограничения](#ограничения-и-известные-проблемы).
- `isTokenStorageSupported: true`, `id: vk-universal`, `target: vk`, `platform: universal`.
- Данные аккаунта VK доступны через три scope: `vkid.personal_info` (по умолчанию: имя, аватар,
  пол, дата рождения), `email`, `phone`. VK ID возвращает значение, только если scope **одновременно**
  включён в кабинете приложения VK ID **и** запрошен в параметре `scope`; для `phone` дополнительно
  нужен подтверждённый бизнес-профиль.

## Свойства безопасности

- **PKCE-verifier существует только на сервере.** 256-битный verifier создаётся на каждый запрос
  авторизации, хранится в сессии взаимодействия Logto и никогда не попадает в URL, лог или ошибку.
- **`redirect_uri` и `state` сохраняются и повторяются байт-в-байт** при обмене кода на токен.
  `state` генерирует Logto, и его проверяет клиент Logto при обработке callback; ядро Logto само
  `state` на сервере **не** сверяет, поэтому коннектор сам привязывает сохранённое значение к
  callback и к ответу token endpoint (защита в глубину) и завершается ошибкой при непустом
  несовпадении.
- **Согласованность субъекта.** `user_id` из ответа token endpoint сравнивается с `user_id` из
  профиля; при несовпадении возвращается ошибка «недействительный access token» вместо привязки
  чужой идентичности.
- **Никаких ответов провайдера в ошибках.** Ошибки содержат только OAuth-код, HTTP-статус и имена
  полей. Access-токены, refresh-токены, `id_token`, коды авторизации и PKCE-verifier никогда не
  попадают в данные ошибки; ошибка таймаута намеренно имеет такую форму, чтобы Logto логировал
  только origin и путь запроса.
- **Защита от захвата аккаунта.** `syncEmail` и `syncPhone` по умолчанию выключены, потому что
  Logto связывает социальную идентичность с **существующим** пользователем Logto по e-mail или
  телефону. Передача предоставленного провайдером, возможно неподтверждённого идентификатора
  превратила бы его в инструмент захвата аккаунта у другого провайдера. E-mail валидируется и
  приводится к нижнему регистру, телефон нормализуется в E.164 или отбрасывается.
- **Ограничение и очистка текста профиля.** Имена обрезаются по длине, управляющие символы,
  Unicode-символы форматирования (bidi, zero-width) и переводы строк удаляются, пустые значения не
  передаются вместо `""`.
- **Враждебные данные провайдера и callback нейтрализуются.** Поля `error` / `error_description` из
  callback (полностью контролируемые параметры строки запроса) и из тел ошибок VK ID очищаются от
  управляющих символов и ограничиваются 200 символами, прежде чем попасть в данные ошибки, поэтому
  они не могут подделать строки лога или переполнить лог Logto. VK user id — значение, которое Logto
  хранит и показывает как социальную идентичность, — обязан соответствовать `[A-Za-z0-9._:-]{1,64}`
  и иначе отклоняется, а не нормализуется. Тела ответов ограничены 1 МиБ, а `apiBaseUrl` не может
  содержать учётные данные в URL.
- **Минимальный сетевой обмен.** Единственные внешние адреса — `authorize`, `oauth2/auth` и
  `oauth2/user_info` VK ID. Ни телеметрии, ни аналитики, ни проверок обновлений, ни доступа к
  файловой системе, ни чтения переменных окружения. Runtime-зависимости — `@logto/connector-kit` и
  `zod`, обе уже есть в образе Logto, поэтому установка коннектора не добавляет в контейнер новых
  пакетов.
- **Проверка конфигурации.** `clientId` обязателен; `apiBaseUrl` должен быть `http(s)`-origin без
  пути, query и fragment, без встроенных учётных данных — HTTPS является документированным дефолтом,
  а явно заданный обычный HTTP — решение администратора для LAN-зеркал и интеграционных тестов;
  `timeout` ограничен диапазоном 1000–60 000 мс.

## Быстрый старт

Есть два пути установки. Оба помещают собранный пакет коннектора в
`/etc/logto/packages/core/connectors/` внутри контейнера Logto, где Logto 1.46.0 ищет коннекторы
**во время выполнения, при старте**.

Что проверяет Logto:

- в каталоге должен быть `package.json` с `name`, начинающимся с `connector-` или
  `@scope/connector-*` — `@ozvix/connector-vkid` этому соответствует;
- диапазон `dependencies["@logto/connector-kit"]` пакета должен покрывать установленную версию
  (5.2.0) — диапазон `^5.2.0` покрывает;
- точка входа — `lib/index.js` (поле `main` этого пакета).

Имя каталога произвольно — загрузчик ориентируется на поле `name` в `package.json`; в этом
репозитории используется `connector-ozvix-vkid`. Копируйте весь каталог пакета (`package.json`,
`lib/` и те ресурсы, которые пакет поставляет: собственный README и файлы логотипа, на которые
ссылаются метаданные коннектора), а не только `lib/`.

### Путь A: производный Docker-образ (рекомендуется)

В репозитории есть многоступенчатый [`Dockerfile`](Dockerfile): он собирает коннектор на Node.js 22
и копирует его в официальный образ:

```bash
docker build -t ozvix/logto-vkid:1.46.0-vkid.1 .
```

Затем укажите в compose-сервисе Logto образ `ozvix/logto-vkid:1.46.0-vkid.1` и пересоздайте
контейнер. Образ неизменяем и воспроизводим, а каждое обновление — это новый тег, поэтому откат
сводится к изменению одной строки. Именно поэтому этот путь рекомендуется для продакшена.

### Путь B: bind-mount

Оставьте официальный образ `svhd/logto:1.46.0` и смонтируйте каталог с хоста **только в
подкаталог коннектора**:

```yaml
# фрагмент docker-compose — полный пример в docs/INSTALL-LOGTO-DOCKER.md
services:
  logto:
    volumes:
      - /opt/logto/connectors/connector-ozvix-vkid:/etc/logto/packages/core/connectors/connector-ozvix-vkid:ro
```

Не монтируйте сам `/etc/logto/packages/core/connectors`: так вы скроете все официальные коннекторы,
включая провайдера, который остаётся запасным. Монтирование должно существовать **до** запуска
Logto: каталог сканируется при старте. Этот путь удобен, когда собрать образ на хосте нельзя.

Точные команды для обоих путей — включая резервные копии, проверку, обновление и откат — в
**[INSTALL-LOGTO-DOCKER.md](docs/INSTALL-LOGTO-DOCKER.md)**.

После любого из путей проверьте, что коннектор загрузился:

1. Admin Console → **Connectors** → **Social connectors** → **Add social connector**. Должен
   быть доступен вариант «VK ID».
2. Если его нет в списке, загрузчик пропустил каталог — см.
   [TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md#connector-is-not-listed-in-the-admin-console).

## Шаг 1: регистрация redirect URI в VK ID

Полная инструкция по шагам кабинета и правилам scope — в **[VK-ID-SETUP.md](docs/VK-ID-SETUP.md)**.
Кратко:

1. Создайте приложение в кабинете VK ID (https://id.vk.ru/about/business/go/). Вход в кабинет
   выполняется через аккаунт VK Бизнес ID, а ключи и настройки приложения ограничены, пока
   бизнес-профиль не подтверждён.
2. Укажите в поле **Базовый домен** публичный хост, который обслуживает Logto, например
   `auth.example.com`.
3. Укажите в поле **Доверенный redirect URL** **точный** callback-адрес коннектора:
   `https://auth.example.com/callback/<connector-id>`.

VK ID сравнивает redirect URI по точному совпадению (домен должен совпадать с базовым доменом),
поэтому копируйте **Callback URI** со страницы коннектора в Admin Console Logto, а не набирайте
вручную. VK ID принимает только порты 80 и 443, поэтому адреса вида `:3001`/`:3002` для
разработки зарегистрировать нельзя.

## Шаг 2: настройка коннектора в Logto

Admin Console → **Connectors** → **Social connectors** → **VK ID** → заполните поля:

| Поле              | Значение                                                                                                                                                                                            |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Client ID         | Числовой идентификатор приложения (`ID приложения`) из кабинета VK ID.                                                                                                                              |
| Service token     | Оставьте пустым для обычного публичного веб-приложения. Нужен только для приложений VK ID, помеченных как _Конфиденциальное_; такие приложения должны вызывать сервис с разрешённого исходящего IP. |
| Scope             | `vkid.personal_info`, если больше ничего не нужно. Добавляйте `email` и/или `phone`, только если они включены в приложении VK.                                                                      |
| Sync e-mail       | Выключено, если не нужно передавать e-mail VK в Logto — сначала прочитайте раздел [Связывание аккаунтов](#связывание-аккаунтов-и-почему-синхронизация-e-mail-и-телефона-выключена-по-умолчанию).    |
| Sync phone number | Выключено, по той же причине; Logto предпочитает совпадение по телефону совпадению по e-mail.                                                                                                       |

Поля redirect URI в конфигурации нет: коннектор всегда использует callback URI, который
сгенерировал для него Logto. Поля **`clientSecret` тоже нет** — в обмене кода на токен VK ID нет
параметра `client_secret`. Не вставляйте никуда _Защищённый ключ_ приложения VK.

## Шаг 3: включение VK ID в сценарии входа

Admin Console → **Sign-in experience** → **Social sign-in** → добавьте коннектор VK ID и сохраните.
(Этот репозиторий рассчитан на установку в режиме «только социальный вход»: регистрация и вход по
e-mail и паролю отключены, имя и аватар берутся из профиля VK, e-mail и телефон — только при
включённой синхронизации.)

Прежде чем переходить на «только социальный вход», убедитесь, что остаётся рабочим хотя бы один
социальный коннектор (например, Yandex ID), чтобы администратор не заблокировал себе доступ.

## Справочник по конфигурации

Семь полей, все редактируются в Admin Console. Обязательно только `clientId`.

| Поле           | Тип в консоли                        | Обязательно | По умолчанию         | Описание                                                                                                                                                                                                                                                                                                                                                    |
| -------------- | ------------------------------------ | ----------- | -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `clientId`     | text                                 | **да**      | —                    | Идентификатор приложения VK ID (`ID приложения`), числовой. Передаётся как `client_id` в запросе авторизации, при обмене кода на токен и в query `user_info`.                                                                                                                                                                                               |
| `serviceToken` | text (хранится как конфиденциальное) | нет         | пусто                | Только для приложений VK ID, помеченных как _Конфиденциальное_ (`Сервисный ключ доступа`). Передаётся как POST-параметр `service_token` при обмене кода на токен. Конфиденциальные приложения должны также обращаться с разрешённого IP. Оставьте пустым для публичного веб-приложения. Это не _Защищённый ключ_.                                           |
| `scope`        | multiline text                       | нет         | `vkid.personal_info` | Scope VK ID через пробел. Значение возвращается, только если scope включён в приложении VK **и** запрошен здесь.                                                                                                                                                                                                                                            |
| `syncEmail`    | switch                               | нет         | `false`              | Передавать e-mail VK в Logto. Включение позволяет Logto связать существующий аккаунт с этим e-mail с данной идентичностью VK — см. [Связывание аккаунтов](#связывание-аккаунтов-и-почему-синхронизация-e-mail-и-телефона-выключена-по-умолчанию).                                                                                                           |
| `syncPhone`    | switch                               | нет         | `false`              | Передавать номер телефона VK (нормализуется в E.164) в Logto. Та же оговорка, что и для `syncEmail`; при связывании Logto предпочитает телефон, а не e-mail.                                                                                                                                                                                                |
| `apiBaseUrl`   | text                                 | нет         | `https://id.vk.ru`   | Переопределение origin API VK ID. Должен быть origin без пути, query и fragment. По умолчанию HTTPS; явно заданный `http://` допускается для LAN-зеркал и интеграционных тестов, но по обычному HTTP access-токен, код авторизации и PKCE-verifier идут без шифрования. `https://id.vk.com` тоже работает, но отвечает редиректом (HTTP 308) на `id.vk.ru`. |
| `timeout`      | number                               | нет         | `8000`               | Таймаут запросов token и `user_info` в миллисекундах. Допустимый диапазон 1000–60 000.                                                                                                                                                                                                                                                                      |

Проверка конфигурации строгая: пустой `clientId`, `apiBaseUrl` не в виде URL, origin с путём,
query/fragment или встроенными учётными данными, некорректный токен scope или таймаут вне диапазона
дают ошибку конфигурации сразу, а не позже в процессе входа.

## Связывание аккаунтов и почему синхронизация e-mail и телефона выключена по умолчанию

Социальный вход в Logto — это больше, чем аутентификация: когда социальная идентичность приходит
с e-mail или номером телефона, Logto ищет **существующего** пользователя Logto с таким
идентификатором и, если находит, привязывает идентичность VK к этому аккаунту.

Это удобная функция для провайдеров, которые подтверждают идентификаторы. И это угроза
безопасности, когда идентификатор не подтверждён провайдером или подтверждён не так, как вы
ожидаете:

- Если аккаунт VK ID может содержать e-mail, владение которым VK не доказал, передача этого
  e-mail позволяет тому, кто контролирует аккаунт VK, войти как владелец соответствующего аккаунта
  Logto.
- Logto предпочитает совпадение по **телефону**, а не по e-mail, поэтому `syncPhone` — более
  опасный из двух переключателей.
- Аккаунт администратора Logto — особенно привлекательная цель.

Поэтому коннектор возвращает `email` и `phone` в Logto только при включённых `syncEmail` /
`syncPhone`. Но и тогда значение попадёт в профиль лишь при трёх одновременных условиях: scope
включён в кабинете приложения VK ID, scope включён в настроенном параметре `scope`, и включён
соответствующий переключатель синхронизации. Держите оба выключенными, если идентификатор
действительно не нужен в Logto (например, для рассылки писем из Logto) и вы не принимаете
поведение связывания аккаунтов.

## Ограничения и известные проблемы

| Ограничение                                     | Подробности                                                                                                                                                                                                                                                                                                                                                              |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Нет обновления токенов                          | Access-токен VK ID живёт **1 час**; refresh-токен — **180 дней**, но он одноразовый с ротацией (повторное использование старого аннулирует сессию), а запрос обновления в VK требует ещё и `device_id`, который не сохраняется. Коннектор передаёт refresh-токен в хранилище Logto, но не обновляет его, поэтому сохранённый access-токен устаревает примерно через час. |
| Хранилище токенов без обновления                | `isTokenStorageSupported` = `true`; Logto сохраняет то, что вернул обмен кода на токен. Рассматривайте это как возможность аудита/использования в течение часа, а не как долговременный делегированный доступ.                                                                                                                                                           |
| Только порты 80/443                             | VK ID поддерживает redirect URI только на портах 80 и 443. Dev-экземпляр Logto на `:3001` не может быть redirect-адресом VK ID; используйте публичный HTTPS-хост на 443 (продакшен) или локальный HTTPS на 443.                                                                                                                                                          |
| Длина `state`                                   | VK OAuth 2.1 требует `state` не короче 32 символов, и официальные SDK VK соблюдают этот минимум. Стандартный Logto 1.46.0 генерирует 14 символов, поэтому производный образ при сборке патчит Experience-бандл до 46 символов (и падает, если патч не применим). См. [TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md).                                                      |
| `id_token` не проверяется                       | VK ID — это OAuth 2.1 с собственным JWT, а не OpenID Connect: нет discovery-документа, нет JWKS, нет claim'ов `iss`/`aud`. Идентичность берётся из `user_info` по TLS с токеном, полученным непосредственно от VK ID; JWT никогда не используется как источник доверия.                                                                                                  |
| Нет выхода и отзыва                             | Выход из Logto не завершает сессию VK ID, а отозванные в VK разрешения замечаются только при следующем входе.                                                                                                                                                                                                                                                            |
| Контракт ошибок callback не документирован      | VK ID документирует, что при ошибке авторизации пользователь видит страницу ошибки, но не то, передаётся ли при этом параметр `error` в redirect URI. Коннектор обрабатывает оба варианта (callback с `error` становится ошибкой авторизации, callback без `code` — общей ошибкой авторизации), но гарантировать понятное сообщение нельзя.                              |
| Коды ошибок token endpoint не стандартизированы | VK ID документирует только то, что некорректный запрос к token endpoint возвращает `404 NOT FOUND`. Поэтому любой 4xx от token endpoint трактуется как недействительный код авторизации; ветвления по конкретным строкам ошибок нет.                                                                                                                                     |
| Лимиты запросов                                 | Для публичных приложений VK ID — **15 000 запросов в сутки на IP**; для конфиденциальных — **120 000 в сутки на приложение** (и нужен статический разрешённый исходящий IP).                                                                                                                                                                                             |
| Поддержка версий Logto                          | Проверено только на self-hosted Logto OSS 1.46.0. Остальные версии Logto и облачный Logto Cloud — UNVERIFIED: коннектор рассчитан на self-hosted Logto OSS.                                                                                                                                                                                                              |
| Флаг `verified` игнорируется                    | Флаг подтверждения данных аккаунта VK (серая галочка) ничего не говорит о владении e-mail, поэтому он не отображается ни в одно поле Logto.                                                                                                                                                                                                                              |

## Диагностика

Начните с **[TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md)**: таблица «симптом → причина →
решение», разделы о чтении логов Logto и об откате. Три самые частые причины:

1. Коннектор отсутствует в Admin Console — загрузчик пропустил каталог (имя, точка входа или
   проверка версии connector-kit). Проверьте в логе контейнера Logto строки с `[load-connector]`.
2. VK ID показывает страницу ошибки после экрана согласия — зарегистрированный **Доверенный
   redirect URL** не совпадает с callback URI точно или использует порт, отличный от 80/443.
3. В пользователе Logto нет e-mail или телефона — `syncEmail`/`syncPhone` по умолчанию выключены,
   и scope должен быть включён ещё и в приложении VK.

## Разработка

```bash
npm ci            # установка зависимостей (Node.js >= 22)
npm run build     # tsup → lib/index.js (ESM-бандл)
npm run check     # tsc --noEmit
npm run lint      # eslint
npm test          # юнит-тесты vitest
npm run verify    # check + lint + test + build
```

`npm test` запускает юнит-тесты из `tests/`; они не обращаются ни к VK ID, ни к Logto. Локальное
интеграционное окружение в контейнерах (Logto 1.46.0 + PostgreSQL + mock-сервер VK ID) и точные
команды описаны в [LOCAL-TESTING.md](docs/LOCAL-TESTING.md).

**Реальный сквозной вход через VK ID — ручной шаг**: нужны зарегистрированное приложение VK ID,
redirect URI на порту 443 и настоящие учётные данные VK. Чек-лист — раздел
**Manual verification checklist** в [VK-ID-SETUP.md](docs/VK-ID-SETUP.md#manual-verification-checklist);
проект этот чек-лист **не выполнял**.
